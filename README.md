# browseruse-lab

Полигон browser-use: агент ходит по сайту, отдаёт **типизированные** данные,
результат **проверяется детерминированно** — инвариантами и сверкой с независимым эталоном.

Это макет банковского коннектора. Модель не решает, правильны ли данные; она их только достаёт.

## Установка (уже сделана)

```bash
uv venv --python 3.12
uv pip install --python .venv/bin/python browser-use python-dotenv
.venv/bin/browser-use install     # свой Chromium
```

Ключ провайдера — в `.env` (в `.gitignore`, права 600). Провайдер выбирается
по имени модели: `gpt-*` → OpenAI, `claude-*` → Anthropic, `gemini-*` → Google.

## Файлы

| Файл | Что делает |
|---|---|
| `extractor.py` | Ядро: `extract(task, schema, model)` → провалидированный pydantic-объект или ошибка. Ретраи, учёт токенов, реальный подсчёт цены по реестру LiteLLM. |
| `cbr_rates.py` | Полигон: таблица курсов ЦБ. Инварианты + сверка с официальным XML ЦБ. |
| `run_task.py` | Свободная задача на любой модели, метрики по шагам/цене. |
| `smoke_browser.py` | Проверка браузерного слоя без LLM. |

## Запуск

```bash
.venv/bin/python cbr_rates.py                          # один прогон
.venv/bin/python cbr_rates.py --runs 3 --out rates.json # проверка стабильности
.venv/bin/python cbr_rates.py --model claude-sonnet-4-6
```

Код возврата: `0` — данные получены и проверка пройдена, `1` — иначе. Годится для cron.

## Что выяснено на практике

- **`max_completion_tokens` по умолчанию 4096** — длинная таблица не влезает,
  структурированный вывод рвётся посередине. `extractor.py` поднимает до 32000.
  Разница на той же задаче: 15 шагов / 271 с / $0.060 → 3 шага / 85 с / $0.025.
- **Координатный клик** включается только для моделей из захардкоженного списка
  (`agent/service.py:327`): `claude-sonnet-4`, `claude-opus-4`, `claude-fable-5`,
  `gemini-3-pro`, `browser-use/`. Ни `gpt-5-mini`, ни `haiku`, ни `claude-*-5` в него не входят —
  они кликают только по индексам DOM.
- **Мелкие модели не восстанавливаются после ошибки инструмента.** Без явного правила
  в `extend_system_message` gpt-5-mini упёрлась в невалидный CSS-селектор и сдалась.
- **Счётчик цены browser-use знает не все модели** — для `gpt-5-mini` показывал `$0.0000`.
  `extractor.cost_of()` считает сам по реестру LiteLLM.
- **У uv-питона нет системного CA-бандла** — внешние HTTPS-запросы делать через `certifi`.
- **Агент по своей воле лез писать файлы и делать скриншоты**, тратя на это шаги.
  `extractor.NOISY_ACTIONS` вырезает 9 лишних действий из тулсета. Средняя цена прогона
  упала с $0.070 до $0.045, но разброс по шагам (3–15) остался — источник не только в них.

## Как агент выбирает, куда кликать (проверено на исходниках + экспериментом)

1. `dom/serializer/serializer.py:645` — индекс элемента **это и есть CDP `backendNodeId`**
   (синтетический номер выдаётся только при коллизии).
2. Индекс присваивается элементу, только если он **интерактивен И видим**
   (`_assign_interactive_indices_and_mark_new_nodes`).
3. `browser/session.py:2437` — `click(index)` ищет узел **только в `_cached_selector_map`**,
   которую сторож DOM перестраивает на каждом шаге. Нет в карте — клик невозможен.
4. Сам клик выполняется по геометрии узла через CDP.

**Индексы не стабильны между загрузками страницы.** Одни и те же фильтры TodoMVC
в четырёх прогонах получили индексы 69/70/71, 67/71/75, 66/70/74, 62/66/70.

**Главное: невидимые элементы выпадают из карты целиком.** В TodoMVC настоящий
`<input class="toggle" type="checkbox">` имеет `opacity: 0` (размер 40×40, позиция на экране есть) —
визуально его рисует стилизованный label. Результат:

```
DOM:            2 задачи, 2 чекбокса, 2 label, 2 кнопки удаления
карта агента:   7 элементов — поле ввода и 6 ссылок. Ни одного чекбокса.
```

Агент физически не может нажать такой чекбокс по индексу: `Element index 1 not available`.
Это не редкий случай — так устроены почти все кастомные чекбоксы, радио и переключатели,
включая фильтры и выбор периода в банковских ЛК.

Обходы: координатный клик (только модели из аллоулиста — у элемента есть реальная геометрия),
либо Playwright с явным селектором, который фильтр видимости не применяет.

## Замеренная надёжность

6 прогонов подряд на `gpt-5-mini`, задача «вытащить таблицу курсов ЦБ»:
**6/6 успешных**, каждый раз 54 строки из 54, все значения совпали с XML ЦБ до 4-го знака.

| | шагов | время | цена |
|---|---|---|---|
| лучший | 3 | 77 с | $0.022 |
| худший | 19 | 313 с | $0.086 |
| типично | 6–15 | ~2–4 мин | ~$0.045 |

Разброс большой, но на корректность данных он не влияет — только на счёт.

## Принцип, который здесь зашит

Модель ошибается тихо: возвращает правдоподобные, но неполные данные.
Поэтому проверка всегда снаружи модели и всегда кодом:

1. схема (pydantic) — форма данных;
2. инварианты — дубли, знаки, пропуски, обнуления;
3. независимый эталон — здесь XML ЦБ, в банке это API бизнес-счёта или
   сходимость `остаток_начало + оборот = остаток_конец`.

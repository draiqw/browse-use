# browseruse-lab

Харнесс поверх [browser-use](https://github.com/browser-use/browser-use): агент ходит по
странице, отдаёт **типизированные** данные, результат **проверяется детерминированно** —
инвариантами и сверкой с независимым эталоном.

Модель не решает, правильны ли данные; она их только достаёт. Проверяет код.

Три вещи сменные и не зашиты в логику:

- **модель** — любой из 14 провайдеров browser-use плюс любой OpenAI-совместимый эндпоинт;
- **профиль** — как агенту разрешено вести себя на странице (только чтение, клики по индексам,
  клики по координатам, без размышлений, ванильный browser-use);
- **бэкенд** — чем крутится задача; браузер через browser-use или песочница с шеллом
  на [Cloudflare Computer](cfcomputer/README.md).

Апстрим при этом не форкается и не патчится: `python -m harness doctor` проверяет,
что все допущения о его внутренностях ещё верны.

## Установка

```bash
uv venv --python 3.12
uv pip install --python .venv/bin/python -r backup/requirements.lock.txt
.venv/bin/browser-use install      # свой Chromium
```

Ключи провайдеров — в `.env` рядом с проектом (в `.gitignore`, права 600).
Что готово к работе прямо сейчас, показывает `python -m harness models`.

## Команды

```bash
.venv/bin/python -m harness doctor    # целы ли допущения об апстриме
.venv/bin/python -m harness models    # какие провайдеры готовы
.venv/bin/python -m harness tasks     # задачи и профили

# одна задача, одна модель
.venv/bin/python -m harness run -t cbr -m openai:gpt-5-mini

# стабильность: три повтора
.venv/bin/python -m harness run -t cbr -m openai:gpt-5-mini -r 3 --out runs.json

# сравнение профилей на одной модели
.venv/bin/python -m harness run -t clickgate -m openai:gpt-5-mini -p act -p act-coords

# сравнение моделей между собой
.venv/bin/python -m harness run -t hn -m openai:gpt-5-mini -m anthropic:claude-haiku-4-5-20251001 --md
```

Код возврата: `0` — все прогоны сошлись с эталоном, `1` — иначе. Годится для cron.

Из питона:

```python
from harness import run
rep = run("cbr", "openai:gpt-5-mini")
print(rep.verified, rep.problems, rep.cost)
```

## Устройство

| Модуль | Что делает |
|---|---|
| `harness/models.py` | Модель по строке `провайдер:модель`. Какие kwargs поддерживает класс — выясняется интроспекцией, а не захардкожено: у ChatOllama нет температуры, у OpenAI лимит ответа зовётся `max_completion_tokens`, у Anthropic `max_tokens`. |
| `harness/profiles.py` | Профили поведения. Здесь же принудительное включение кликов по координатам — минуя зашитый в апстрим список из пяти моделей. |
| `harness/task.py` | Задача = текст + схема + функция проверки. Без проверки задача не регистрируется. |
| `harness/backends.py` | Прогон через browser-use, сбор шагов, токенов, действий, ошибок, реальной цены. |
| `harness/runner.py` | Матрица задача × модель × профиль × повторы. |
| `harness/report.py` | Строка на прогон и сводная таблица; markdown по флагу. |
| `harness/upstream.py` | Семь проверок допущений об апстриме — то, что ломается при его обновлении. |
| `harness/pricing.py` | Цена по реестру LiteLLM с недельным кэшем: счётчик browser-use знает не все модели и молча показывает $0.0000. |
| `harness/fixtures.py` | Локальный http-сервер для офлайновых задач: `file://` browser-use блокирует. |
| `tasks/cbr.py` | Таблица курсов ЦБ против официального XML. Макет банковского коннектора. |
| `tasks/hn.py` | Hacker News против Firebase API самого HN. Быстрый общий тест. |
| `tasks/clickgate.py` | Офлайновая задача на клики: кастомные тогглы с `opacity:0`, эталон известен точно. |
| `extractor.py` | Прежний интерфейс полигона, теперь тонкая обёртка над `harness`. |
| `index_probe.py`, `click_demo.py`, `click_audit.py` | Эксперименты, на которых построены выводы ниже. |

### Профили

| Профиль | Что меняет |
|---|---|
| `extract` | Только чтение: навигация, `extract_structured_data`, `done`. Всё остальное выключено — агент по своей инициативе лез писать файлы и жать кнопки, это лишние шаги и деньги. |
| `extract-flash` | То же без размышлений: быстрее и дешевле, точность ниже. |
| `act` | Манипуляции по индексам элементов, правила про нестабильность индексов. `evaluate` выключен. |
| `act-coords` | Клики по координатам **принудительно, любой модели**, плюс зрение. `evaluate` выключен. |
| `act-js` | То же, но с `evaluate`: модели разрешено обойти интерфейс скриптом. |
| `raw` | Ванильный browser-use без наших правил — база для сравнения. |

Почему в `act` и `act-coords` выключен `evaluate`: на первом же прогоне модель не стала
кликать вообще — написала JS, нашла нужные подписи по тексту и переключила чекбоксы
напрямую. Задача решена, но профиль в этот момент мерил не то, ради чего заведён.
Для сравнения оставлен отдельный профиль `act-js`, где такой путь разрешён.

### Про клики по координатам

Апстрим включает их пяти моделям по подстроке в имени (`agent/service.py`): `claude-sonnet-4`,
`claude-opus-4`, `claude-fable-5`, `gemini-3-pro`, `browser-use/`. Всем остальным остаются
только клики по индексам. Профиль `act-coords` вызывает `Tools.set_coordinate_clicking(True)`
до конструктора `Agent` — схема действия `click` при этом меняется:

```
act         параметры click: ['index']
act-coords  параметры click: ['coordinate_x', 'coordinate_y', 'index']
```

Форк для этого не нужен, но нужна страховка: `doctor` проверяет и наличие метода, и то,
что апстрим по-прежнему собирает схему действий позже, чем мы её меняем.

## Как добавить свою задачу

Задача обязана уметь проверять себя. Без этого «агент что-то вернул» и «агент вернул
правду» — неразличимые события, а на деньгах так нельзя.

```python
# tasks/mybank.py
from pydantic import BaseModel, Field
from harness.task import Task, register

class Statement(BaseModel):
    balance_start: float
    balance_end: float
    turnover: float
    operations: list[dict]

def verify(d: Statement) -> list[str]:
    problems = []
    # инвариант, эталон не нужен: остаток сходится с оборотом
    if abs(d.balance_start + d.turnover - d.balance_end) > 0.01:
        problems.append(f"{d.balance_start} + {d.turnover} != {d.balance_end}")
    # сверка с независимым источником, если он есть
    return problems

register(Task(name="mybank", prompt="Открой ... и извлеки выписку за период",
              schema=Statement, verify=verify, profile="extract", max_steps=25))
```

Добавь импорт в `tasks/__init__.py` — задача появится в `python -m harness tasks`
и станет доступна всем моделям и профилям сразу.

Источники эталона по убыванию надёжности: официальный API того же банка → арифметический
инвариант (`остаток_начало + оборот = остаток_конец`) → сверка двух независимых прогонов
между собой. Последнее ловит только случайные ошибки, но не систематические.

## Чего харнесс не делает

- Не форкает и не патчит browser-use. Все изменения поведения — через публичный API.
- Не судит о правильности данных моделью. Судит код в `verify`.
- Не хранит и не логирует секреты: ключи только в `.env`, он в `.gitignore`.
- Не умеет обходить капчу, 2FA и антибот-защиту, и не пытается.

## Что выяснено на практике

- **`max_completion_tokens` по умолчанию 4096** — длинная таблица не влезает,
  структурированный вывод рвётся посередине. `extractor.py` поднимает до 32000.
  Разница на той же задаче: 15 шагов / 271 с / $0.060 → 3 шага / 85 с / $0.025.
- **Координатный клик** включается только для моделей из захардкоженного списка
  (`agent/service.py:327`): `claude-sonnet-4`, `claude-opus-4`, `claude-fable-5`,
  `gemini-3-pro`, `browser-use/`. Ни `gpt-5-mini`, ни `haiku`, ни `claude-*-5` в него не входят —
  они кликают только по индексам DOM.
- **Мелкие модели не восстанавливаются после ошибки инструмента.** Без явного правила
  в `extend_system_message` gpt-5-mini упёрлась в невалидный CSS-селектор и сдалась.
- **Счётчик цены browser-use знает не все модели** — для `gpt-5-mini` показывал `$0.0000`.
  `extractor.cost_of()` считает сам по реестру LiteLLM.
- **У uv-питона нет системного CA-бандла** — внешние HTTPS-запросы делать через `certifi`.
- **Агент по своей воле лез писать файлы и делать скриншоты**, тратя на это шаги.
  `extractor.NOISY_ACTIONS` вырезает 9 лишних действий из тулсета. Средняя цена прогона
  упала с $0.070 до $0.045, но разброс по шагам (3–15) остался — источник не только в них.

## Что показала матрица на задаче clickgate

`gpt-5-mini`, страница с кастомными тогглами, по два прогона на профиль, эталон известен точно:

| профиль | что разрешено | сошлось | шаги min/med/max | время | цена/прогон |
|---|---|---|---|---|---|
| `act` | клики по индексам | **0/2** | 24/25/25 | 320s | $0.0871 |
| `act-coords` | клики по координатам | **0/2** | 20/25/25 | 427s | $0.0792 |
| `act-js` | `evaluate` | **2/2** | 10/21/21 | 122s | $0.0562 |

Что за этим стоит:

- **Клики по индексам невозможны в принципе.** Проверено без LLM: в карте элементов агента
  на этой странице **ноль** интерактивных элементов, при том что в DOM 4 чекбокса и 8 подписей.
  Агент 25 шагов подряд зовёт `find_elements`, не получает ни одного индекса и упирается в потолок шагов.
- **Клики по координатам работают механически, но модель мажет.** 30 вызовов вида
  `click(index=None, coordinate_x=120, coordinate_y=260)` реально ушли в браузер — значит,
  разблокировка через `set_coordinate_clicking` работает. Но `gpt-5-mini` включила не те тогглы:
  в одном прогоне вместо «Специального счёта» и «Депозита» оказался включён «Валютный счёт».
  Попасть в переключатель 44×24 пикселя по скриншоту эта модель не умеет.
- **JS решает задачу с первого захода**, вдвое быстрее и в полтора раза дешевле — и полностью
  минуя интерфейс.

Отсюда практический вывод для банковского коннектора: **на кастомных контролах агент не кликает.**
Либо скриптовый слой (селекторы, JS, CDP) делает это детерминированно, либо нужна модель,
которая реально умеет целиться по скриншоту. Проверить второе на этом стенде пока нельзя —
в `.env` лежит только ключ OpenAI.

## Как агент выбирает, куда кликать (проверено на исходниках + экспериментом)

1. `dom/serializer/serializer.py:645` — индекс элемента **это и есть CDP `backendNodeId`**
   (синтетический номер выдаётся только при коллизии).
2. Индекс присваивается элементу, только если он **интерактивен И видим**
   (`_assign_interactive_indices_and_mark_new_nodes`).
3. `browser/session.py:2437` — `click(index)` ищет узел **только в `_cached_selector_map`**,
   которую сторож DOM перестраивает на каждом шаге. Нет в карте — клик невозможен.
4. Сам клик выполняется по геометрии узла через CDP.

**Индексы не стабильны между загрузками страницы.** Одни и те же фильтры TodoMVC
в четырёх прогонах получили индексы 69/70/71, 67/71/75, 66/70/74, 62/66/70.

**Главное: невидимые элементы выпадают из карты целиком.** В TodoMVC настоящий
`<input class="toggle" type="checkbox">` имеет `opacity: 0` (размер 40×40, позиция на экране есть) —
визуально его рисует стилизованный label. Результат:

```
DOM:            2 задачи, 2 чекбокса, 2 label, 2 кнопки удаления
карта агента:   7 элементов — поле ввода и 6 ссылок. Ни одного чекбокса.
```

Агент физически не может нажать такой чекбокс по индексу: `Element index 1 not available`.
Это не редкий случай — так устроены почти все кастомные чекбоксы, радио и переключатели,
включая фильтры и выбор периода в банковских ЛК.

Обходы: координатный клик (только модели из аллоулиста — у элемента есть реальная геометрия),
либо Playwright с явным селектором, который фильтр видимости не применяет.

## Замеренная надёжность

6 прогонов подряд на `gpt-5-mini`, задача «вытащить таблицу курсов ЦБ»:
**6/6 успешных**, каждый раз 54 строки из 54, все значения совпали с XML ЦБ до 4-го знака.

| | шагов | время | цена |
|---|---|---|---|
| лучший | 3 | 77 с | $0.022 |
| худший | 19 | 313 с | $0.086 |
| типично | 6–15 | ~2–4 мин | ~$0.045 |

Разброс большой, но на корректность данных он не влияет — только на счёт.

## Принцип, который здесь зашит

Модель ошибается тихо: возвращает правдоподобные, но неполные данные.
Поэтому проверка всегда снаружи модели и всегда кодом:

1. схема (pydantic) — форма данных;
2. инварианты — дубли, знаки, пропуски, обнуления;
3. независимый эталон — здесь XML ЦБ, в банке это API бизнес-счёта или
   сходимость `остаток_начало + оборот = остаток_конец`.

## Вторая площадка: песочница вместо браузера

Браузерная часть отвечает на вопрос «может ли модель нажать кнопку». Оказалось,
что на нестандартных контролах — не может (см. матрицу clickgate выше). Вопрос
рядом: а сделает ли модель работу, если кнопок нет вообще, а есть файлы и шелл.

Для этого в `cfcomputer/` лежит воркер на
[`@cloudflare/computer`](https://github.com/cloudflare/computer) — воркспейс с
файловой системой в Durable Object и шеллом `just-bash` в Dynamic Worker.
Поднимается локально через `wrangler dev`, аккаунт Cloudflare не нужен, сети у
песочницы нет. Подробности и что именно внутри доступно — в
[`cfcomputer/README.md`](cfcomputer/README.md).

Питонья обвязка — пакет `sandbox/`, устроенный так же, как браузерный харнесс:
задача сама себя проверяет, модель сменная, отчёт с токенами и ценой.

```sh
python -m sandbox doctor                        # песочница вообще работает?
python -m sandbox tasks                         # задачи и их правильные ответы
python -m sandbox run -m openai:gpt-5-mini -t ledger needle
python -m sandbox run -m anthropic:claude-haiku-4-5 openai:gpt-5-mini -n 3 --save cmp.json
```

Задач две, обе с точным эталоном — фикстуры генерируются детерминированно,
поэтому правильный ответ считается на нашей стороне из тех же данных:

| задача | что делать | ловушка |
|---|---|---|
| `ledger` | сумма трат по категориям за июль 2026 по 240 операциям, только `posted` | рядом лежит прошлогодняя выписка того же формата; треть строк — `pending`/`declined` |
| `needle` | найти ключ `TOKEN-` + 8 шестнадцатеричных знаков в дереве из 60 файлов | пять приманок, одна из них — `TOKEN-4C7A19E31`, у которой правильный префикс |

Инструментов у агента четыре: `bash`, `write_file`, `read_file`, `done`. Схемы
описаны один раз нейтрально и переводятся в формат провайдера
(`sandbox/tools.py`), чтобы сравнение моделей меряло модели, а не разницу в
формулировках схем.

### Что уже замерено

`gpt-5-mini`, по одному прогону на задачу:

| задача | сошлось | шагов | время | цена |
|---|---|---|---|---|
| `needle` | да | 6 | 27с | $0.0032 |
| `ledger` | да | 5 | 14с | $0.0038 |

Работа настоящая, не угадывание: в `ledger` модель посчитала одним вызовом
`awk -F, ... $2 ~ /^2026-07-/ && $5=="posted" {a[$3]+=$4}`; в `needle` `grep -E`
дал два совпадения (приманка с правильным префиксом сработала), и модель
развела их, прочитав оба файла.

**Haiku пока не запущен: в `.env` нет `ANTHROPIC_API_KEY`.** Всё остальное под
него готово — цикл tool-use под Anthropic Messages API написан и лежит в
`sandbox/agent.py`, команда та, что в примере выше.

## Резервные копии чужого кода

Апстрим — чужой репозиторий, его могут удалить, переписать историю или сломать API мажорным
релизом. Поэтому всё, от чего зависит лаборатория, лежит рядом.

```
backup/browser-use-git/       полный клон апстрима: 10055 коммитов, 146 тегов (локально, не в git)
backup/browser-use-0.13.8/    исходники рабочего тега, распакованные из git archive (в git)
backup/wheels/                103 колеса — всё окружение целиком, 57 МБ (локально, не в git)
backup/wheels.sha256          контрольные суммы колёс
backup/requirements.lock.txt  точные версии 103 пакетов
backup/PROVENANCE.txt         откуда снято, какие коммиты, что проверено
backup/restore.sh             пересборка окружения без интернета
```

Восстановление после любой поломки апстрима:

```bash
./backup/restore.sh     # сверяет суммы, сносит .venv, ставит всё из backup/wheels
```

Проверено 2026-08-23: скрипт отработал целиком, окружение поднялось, `smoke_browser.py` прошёл.

Апстрим в `.venv` не патчится — все 182 файла пакета совпадают с хешами из `RECORD`. Оболочка
лежит поверх публичного API (`Agent`, `Browser`, `Tools`, `Chat*`), так что при обновлении
ломаться может только этот стык, а не наш код внутри чужого.

То же сделано для `@cloudflare/computer` — он помечен апстримом как **PREVIEW ONLY**, то есть
API там меняться будет:

```
backup/cloudflare-computer-git/       полный клон: 813 коммитов, 19 тегов (локально, не в git)
backup/npm/cloudflare-computer-0.2.1.tgz  опубликованный пакет, ровно тот, что стоит (в git, 2,4 МБ)
backup/npm.sha256                     контрольная сумма
```

Восстановление: `cd cfcomputer && npm install ../backup/npm/cloudflare-computer-0.2.1.tgz`.
Проверено 2026-08-24: пакет ставится из тарбола и импортируется. Версия закреплена точно,
без `^`. Полного офлайн-зеркала npm-зависимостей, как `backup/wheels` для питона, нет:
wrangler и typescript тянутся из сети.
